# stats.avar.me

Открытая статистика экосистемы avar.me. Сайт статический: сбор идёт отдельным заданием, посетители читают готовый JSON.

Каждый источник — отдельный модуль в `collectors/`. Список модулей живёт в `collectors/registry.py`. Планировщик не знает деталей провайдера: он вызывает `collect()`, сохраняет историю этого источника и идёт дальше. Ошибка или отсутствие секрета у одного модуля не стирает и не блокирует остальные.

Сейчас включены Telegram-каналы, стикерпак и Cloudflare. App Store, Google Play и телеметрия ботов уже реализованы и выключены в `config.yaml`. Их подключение — это `enabled: true` и секреты, без перестройки сайта.

## Локальная разработка

Нужен Python 3.12+.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
pytest
python scripts/publish.py
```

Сайт лежит в `site/`. Из этой папки:

```bash
python -m http.server 8765
```

Откройте http://127.0.0.1:8765/ . Пока нет секретов, карточки показывают «не настроено» и «Нет данных». Это не нули: пропущенные дни не заполняются.

Демонстрационные ряды для вёрстки, отдельно от публикации:

```bash
python scripts/preview.py
```

Они пишутся в `site/preview-data/` и открываются как `index.html?preview=1`. На странице есть пометка, что это не статистика проекта. Каталог в `.gitignore`. Публикация такого файла запрещена: `python scripts/check_public.py`.

Сбор с секретами:

```bash
set -a && source .env && set +a
python scripts/collect.py
```

Шаблон переменных — `.env.example`. Файл `.env` не коммитится.

Повторно собрать JSON из уже сохранённой истории, не ходя в API:

```bash
python scripts/publish.py
```

## Конфигурация

`config.yaml`. Секретов в нём нет.

- `telegram_channels` — публичные каналы. Сейчас включены `@avarlangme`, `@avar_kino`, `@avar_film`. Чат `@avarme_chat` выключен.
- `telegram_stickers` — набор `AvarMe` («Хӏарпик»).
- `cloudflare.sites` — девять сайтов из первого запуска. У каждого пустые `site_tag` и `zone_id`, их нужно заполнить.
- `apple`, `google_play`, `telegram_bots` — `enabled: false`.

`lookback_days` у Cloudflare задаёт, сколько дней запрашивать за один запуск (по умолчанию 30). Более старые точки, уже лежащие в истории, при этом не удаляются. `freshness_hours` (36) — после какого срока успешные данные помечаются как устаревшие.

Интерфейс русский. Подписи показателей задаёт `core/catalog.py` и попадает в JSON. Подписи кнопок и периодов — объект `I18N.ru` в `site/app.js`. Новый язык — второй объект рядом и перевод каталога, а не новая вёрстка.

## Учётные данные

Только переменные окружения или секреты GitHub Actions. В репозиторий не кладутся ключи, токены и сырая телеметрия.

| Переменная | Модуль |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | каналы и стикерпаки |
| `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID` | сайты |
| `APPLE_KEY_ID`, `APPLE_ISSUER_ID`, `APPLE_PRIVATE_KEY`, `APPLE_APP_ID` | App Store. `APPLE_APP_ID` по умолчанию `6782280983` |
| `GOOGLE_PLAY_CREDENTIALS`, `GOOGLE_PLAY_BUCKET` | Google Play |
| `TELEMETRY_FILE` или `TELEMETRY_URL` и `TELEMETRY_TOKEN` | боты |
| `ANALYTICS_SECRET` | HMAC пользователей внутри процесса бота, на сайт не попадает |

`APPLE_PRIVATE_KEY` и `GOOGLE_PLAY_CREDENTIALS` — либо PEM/JSON целиком (переносы строк как `\n`), либо путь к файлу вне репозитория.

## Права API

**Telegram.** Любой бот, которому доступен канал. Для числа подписчиков вызывается `getChatMemberCount`. Для набора — `getStickerSet`. Установок и пользователей набора этот метод не отдаёт.

**Cloudflare.** Токен с правом Account Analytics Read. Если заполнен `zone_id`, тому же токену нужно чтение аналитики зоны. `site_tag` — это идентификатор из `data-cf-beacon`, он не равен ни account id, ни zone id. Один site tag может покрывать несколько хостов, поэтому ряды фильтруются по `requestHost`.

**App Store Connect.** Ежедневное скачивание отчётов — ключ Sales and Reports или Finance. Создать первый `ONGOING`-запрос может только ключ Admin, и только явной командой:

```bash
python scripts/apple_request.py --confirm
```

Ежедневный сбор сам запрос не создаёт. Пока Apple не прислала первый файл (обычно 1–2 дня), история пустая. Экземпляры отчёта живут около 35 дней, поэтому задание должно ходить каждый день и оставлять свою копию. Более новый `processingDate` заменяет строки той же даты, а не прибавляется к ним. Данные моложе двух дней помечаются как неполные.

**Google Play.** Сервисный аккаунт с правом View app information и областью `devstorage.read_only`. Бакет — URI со страницы Play Console → Download reports → Statistics, обычно `pubsite_prod_rev_…`. Play Developer Reporting API установки не отдаёт (там виталы: сбои и ANR), поэтому модуль читает ежемесячные CSV `stats/installs`.

## GitHub Actions

`.github/workflows/update-stats.yml` запускается каждый день в 03:00 UTC и вручную. Шаги: сбор всех включённых модулей, проверка что JSON не демонстрационный и без секретов, коммит `data/history`, `data/public` и `site/data`, выкладка `site/` на GitHub Pages.

`.github/workflows/deploy-pages.yml` публикует `site/` при push в `main`, если изменились HTML, CSS или JS. Так же устроены `ios` и `js` в этой папке `avar`. Оба workflow используют общую группу `pages`, поэтому выкладки не перекрывают друг друга.

Публикация на GitHub Pages:

1. Settings → Pages → Source: **GitHub Actions**.
2. Домен `stats.avar.me` настраиваете вы: DNS-запись и Custom domain в тех же настройках Pages. Файл `CNAME` в репозиторий не кладётся. Если захотите держать домен в файле, как `ios` и `js`, положите `site/CNAME` с одной строкой `stats.avar.me`.
3. Секреты добавляются в Settings → Secrets and variables → Actions. Переменная `TELEMETRY_FILE` задаётся как variable, не secret.

Секреты называются так же, как переменные выше. Ошибка одного включённого источника не отменяет запись остальных: шаг сбора помечен `continue-on-error`, в журнале остаётся его текст без токена. Перед первым запуском включите Pages из GitHub Actions (см. раздел выше).

История в git не должна содержать пользовательских идентификаторов. Файл `data/telemetry/` в репозиторий не входит.

## Cloudflare

Для каждого сайта в панели Web Analytics копируется site tag маяка в `config.yaml`. Маяк — сниппет, который Cloudflare даёт для сайта. Без него в Web Analytics нет просмотров: запросы `curl` туда не попадают. `zone_id` нужен только если хотите отдельно показать HTTP-запросы зоны, включая автоматический трафик. Эти запросы подписаны как HTTP-запросы и не складываются с визитами.

Уникальных посетителей набор `rumPageloadEventsAdaptiveGroups` не отдаёт. Карточка этого не скрывает и не подменяет просмотрами. Если Cloudflare вернул `sampleInterval` больше 1, день помечается как оценка.

## Telegram-боты

Bot API не хранит историю использования бота. Счётчики пишет сам бот.

Python, для процесса вне Telegram Serverless:

```python
from integrations.telegram_bot_analytics import track_event

track_event(bot="avar_me_bot", event="dictionary_lookup", success=True, duration_ms=120, user_id=user_id, event_id=update_id)
```

Функция не бросает исключений. В ней нет поля для текста сообщения или поискового запроса. Имя события — латиница, цифры и `_` `.` `:` `-`, до 64 знаков. `event_id` отсекает повтор той же доставки. Идентификатор пользователя в базу не пишется: для дня и месяца считается один и тот же HMAC от `ANALYTICS_SECRET`. Поэтому человек, зашедший в два дня, остаётся одним пользователем месяца. Суточные хеши для этого не объединяются. Дневные хеши и идентификаторы событий хранятся 40 дней, месячные — 400, затем удаляются. Наружу отдаёт только `export_aggregate()`.

Telegram Serverless — JavaScript, без файловой системы и без вызова endpoints из GitHub Actions: endpoint ждёт init data Mini App. Поэтому экспорт — это `npx tgcloud run`.

1. Перенести таблицы из `integrations/tgcloud/schema.snippet.js` в `tgcloud/schema.js` бота и выполнить `npx tgcloud migrate`.
2. Положить `analytics.js` и `exportAnalytics.js` в `tgcloud/lib/`.
3. В обработчике вызывать `track({ bot, event, success, durationMs, userId, eventId })` и не передавать текст сообщения.
4. Один раз записать секрет: модуль `setSecret` в `analytics.js`.
5. По расписанию выполнить `npx tgcloud run lib/exportAnalytics` и сохранить JSON в `TELEMETRY_FILE` или отдавать его по `TELEMETRY_URL`.

Пока `sources.telegram_bots.enabled` равен `false`, модуль в сборе не участвует.

## Публикация

`data/history/<источник>.json` — полная история, по файлу на модуль. Новая ревизия может исправить день. Пустое значение уже записанное число не затирает. `data/public/summary.json` и `history.json` — то, что копируется в `site/data/` и уходит на сайт. Перед записью из документа выкидываются поля вроде `user_id`, `query`, `token`, и запись отменяется, если в тексте нашёлся ключ или токен.

На сайте периоды графиков: 7 дней, 30 дней, 90 дней, год, всё время. Семь и тридцать дней на карточках считаются от последней реальной точки. Если дня в окне нет, он не становится нулём: подпись говорит, за сколько дней из семи есть значения. Снимок подписчиков сравнивается с имеющимся более ранним снимком, а не с выдуманным промежуточным днём.

Светлая и тёмная тема следуют системе, кнопка в шапке запоминает выбор. Графики — Chart.js. Под каждым графиком есть таблица.

## Что собирается

| Показатель | Смысл | Состояние |
| --- | --- | --- |
| Подписчики канала | `getChatMemberCount` на момент снимка. Сумма каналов считает человека в двух каналах дважды | нужен токен бота |
| Стикеров в наборе | длина `stickers` у `getStickerSet` | нужен токен бота |
| Установки стикерпака | — | недоступно. На сайте текст: «Статистика установок недоступна через Telegram API» |
| Просмотры страниц | Web Analytics, `count`, маяк, `bot: 0` | нужны токен, account id и site tag |
| Визиты | Web Analytics, `sum.visits` | то же |
| Уникальные посетители | — | API этого набора их не отдаёт |
| HTTP-запросы и уникальные IP | аналитика зоны, включая автоматы | только если задан `zone_id`; это не посетители |
| Первые загрузки iOS | App Downloads Standard, Download Type = First-time Download | модуль выключен |
| Загрузки без обновлений | First-time Download + Redownload. Обновления и восстановления не входят | модуль выключен |
| Первые установки Android | Daily User Installs обзорного CSV | модуль выключен |
| Установленная аудитория | Current User Installs, по дням не суммируется | модуль выключен |
| Удаления | Daily User Uninstalls | модуль выключен |
| Установки на устройства | Daily Device Installs. Это не пользователи | модуль выключен |
| Запросы бота, успех, ошибки, события, время | собственные счётчики | модуль выключен, пока нет файла телеметрии |
| Уникальные пользователи бота за день и за месяц | число HMAC, не список людей | то же |

Общей цифры «уникальные пользователи экосистемы» нет и не будет: загрузки, подписчики и визиты — разные вещи.

## Устранение неполадок

- Карточка «не настроено» и история на месте. Секрет не задан или, для Cloudflare, ни у одного сайта нет `site_tag`. Старые числа не обнуляются.
- «Устарело». Последний успешный сбор был больше 36 часов назад, либо новый запуск не удался. На карточке остаётся прежнее значение и текст ошибки.
- Канал ответил ошибкой, остальные обновились. Бот не видит этот чат. Сообщение написано у карточки канала, токен в него не попадает.
- Apple: `401` — неверный key id, issuer или PEM, либо срок JWT больше 20 минут. Модуль подписывает токен на 15 минут. `409` при `--confirm` значит, что ONGOING-запрос уже есть. Пустой список экземпляров в первые два дня — нормальное ожидание. `stoppedDueToInactivity` — запрос заглох, потому что отчёты долго не забирали; нужен новый запрос ключом Admin.
- Google Play: пустой бакет — неверное имя или у сервисного аккаунта нет View app information. Нет обзорного файла — итог помечается как оценка по сумме стран и не выдаётся за официальный overview. Свежие три дня помечены как неполные: Play их переписывает.
- Cloudflare вернул `errors` при HTTP 200. Текст ошибки попадает в журнал источника. Проверьте, что токен именно Account Analytics Read и что site tag от этого аккаунта.
- В публичном JSON нашёлся секрет. `scripts/check_public.py` и запись публикации останавливаются. Ищите значение в истории источника, а не маскируйте проверку.
- Демонстрационные данные попали на сайт. Значит, задеплоен `preview-data` или JSON с `"preview": true`. Рабочий деплой берёт только `data/public`.
